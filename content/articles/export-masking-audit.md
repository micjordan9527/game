## 一句话解释

页面查看、创建导出任务和下载导出文件是三个动作，应分别授权。导出还要保存筛选快照、脱敏版本、文件有效期和下载审计，不能把“能看到列表”直接理解为“能带走全部数据”。

## 适合谁看

设计后台导出能力的产品、实现权限与任务的开发、验证越权和过期场景的测试，以及需要使用报表的运营与风控人员。

## 三段权限分别判断

| 动作 | 需要检查 | 不应默认 |
|---|---|---|
| 页面查看 | 身份、角色、租户／站点、字段范围 | 能查看汇总不代表能查看明细 |
| 创建导出 | 导出权限、筛选范围、数据量、用途或审批 | 查看权限不自动包含导出权限 |
| 文件下载 | 当前会话、文件归属、有效期、下载次数或策略 | 拿到旧链接不代表一直可下载 |

后台任务不能只沿用浏览器传来的租户号或筛选条件。服务端应根据当前身份重新确定数据范围，并在任务中保存不可歧义的筛选快照。

## 从筛选到审计的正常流程

确认查看范围 → 固化筛选快照 → 校验导出权限与审批条件 → 生成指定脱敏版本 → 保存文件摘要与有效期 → 下载时再次校验 → 记录成功或拒绝结果。

筛选快照至少说明时间区间、站点、状态、字段、业务时区和口径版本。用户稍后修改页面筛选，不应改变已经创建的任务；重新导出应产生新的任务号。

## 脱敏版本和文件字段

| 字段 | 用途 |
|---|---|
| export_id、requester_id | 识别导出任务和申请人 |
| tenant_id、site_id | 固定数据范围 |
| filter_snapshot、schema_version | 还原筛选与字段定义 |
| masking_policy_version | 说明哪些字段如何脱敏 |
| file_hash、row_count | 核对文件与任务产物，不代表业务数据正确 |
| expires_at、download_result | 控制有效期并记录下载结果 |

脱敏不是把姓名或号码简单替换成同一个符号。需要按用途决定保留格式、局部字符、稳定映射或完全移除，并避免多个字段组合后重新识别个人。

## 虚构示例：导出会员复核清单

演示任务 `EXP-DEMO-001` 由运营在站点 A 创建，筛选北京时间某日、状态为“待复核”的记录。页面允许查看昵称和状态，但导出策略 M2 仅保留会员编号、状态、时间和脱敏联系方式。

任务完成后生成限时下载地址。客服复制地址后切换到无权限站点，或在有效期结束后访问，都应明确拒绝，并记录下载者、任务号、拒绝原因和时间。这个示例只说明控制方式，不代表现有后台已经实现相同字段或时限。

## 异常处理

- 数据范围在任务排队期间被收窄：生成前再次校验；超出范围则终止或只输出仍获准部分，并明确结果。
- 脱敏配置缺失或版本无效：不生成未脱敏文件，记录失败原因。
- 下载链接外泄：服务端仍校验身份与归属；链接失效或撤销后拒绝访问。
- 导出完成但文件校验失败：标记任务失败，不提供可下载状态。
- 审计写入失败：按数据敏感度阻止下载或进入可靠待写机制，不能宣称已经留痕。

## 亲自查看导出任务全过程

本页[导出任务演示](#export-task-demo)使用八条虚构工单，复用列表演示中的编号与状态，联系字段统一为“[已脱敏]”。它与前面的会员清单示例是不同对象，不包含真实个人资料。可实际下载一份示例CSV，文件只含虚构编号、状态、时间与脱敏标记。

| 任务状态 | 如何进入本例状态 | 界面和动作 |
|---|---|---|
| 排队中 | 点击创建导出任务 | 固定任务号、站点、状态条件、条数和M2字段版本；可以开始生成或取消排队 |
| 生成中 | 点击开始生成 | 暂停重复生成；完成前重新核对创建权限与当前站点范围 |
| 可下载 | 本次生成成功 | 展示原快照与文件示例，下载仍独立检查权限、归属和有效期 |
| 生成失败 | 选择模拟一次生成失败后开始 | 不提供文件，保留任务和原因，可按当前条件创建新任务 |
| 已取消 | 主动取消排队，或生成前范围、权限变化 | 不生成可下载产物，保留取消原因 |
| 已过期 | 点击模拟链接过期 | 保留原任务说明，下载请求明确拒绝；需要时创建新任务 |

本例“生成中”用短暂等待展示过程；排队与生成由用户明确触发。有效期标为T到T＋10分钟，过期通过手动模拟观察，不表示本知识库正在运行真实后台定时任务。

## 修改页面条件不改变旧任务

默认在站点A、全部状态下创建`EXP-DEMO-001`，该任务固定八条工单。创建后把“下一任务的记录状态”改为已关闭，原任务仍应显示“站点A／全部／8条”。之后创建的新任务才使用新的条件，并获得新任务号。

这说明筛选快照与当前输入是两份数据。仅保存一个会随着页面变化的筛选对象，无法解释稍后生成的文件到底对应什么范围。

## 三条可操作的权限与过期路径

1. **生成前撤销权限**：创建任务后关闭“允许创建导出”，再开始生成。本例取消任务，不提供文件。
2. **下载前权限变化**：已生成文件后关闭“允许下载文件”，点击请求下载，显示拒绝原因并加入演示事件记录；恢复权限后可按原任务继续请求。
3. **切换站点或链接过期**：站点A的文件在当前站点B范围下被拒绝；模拟过期后也被拒绝，不因为原任务曾完成就继续下载。

创建权限与下载权限不是同一开关。已完成文件的创建权限后来被撤销，并不自动决定能否下载；实际下载仍按当前下载授权、文件归属、有效期等规则判断。本例用于把这些条件分开观察。

## 文件预览与事件记录的边界

M2示例CSV固定四列，不因用户在页面上选择不同筛选而增加敏感字段；预览内容与成功下载内容一致。重新生成使用新任务号，原任务的创建、失败、下载拒绝或成功事件仍保留在本次演示记录中。

这些记录在当前浏览器页面内用于说明，刷新后不保留，也不证明服务端审计已可靠写入。真实系统还需要按权限保存申请人、业务范围、时间、文件摘要和结果，并验证过期策略和存储生命周期。文件已经下载后，页面上的过期状态不能收回本机副本。

相关的范围确认与部分失败行为见[批量操作图解](/articles/admin-bulk-actions#bulk-action-demo)；它改变工单状态，本页导出任务则生成指定范围的文件，两者不要共用一套模糊的“批量成功”提示。

## 风险与注意事项

界面截图只能证明入口和字段如何呈现，不能证明服务端权限、文件存储、过期删除和审计不可篡改都已实现。导出文件还应有保存、分享和销毁规则，避免下载后脱离控制。
